# v0.12 release validation

## Starting state and scope

Audit started on clean `main` at `ef9f652a39ffd50425d406dfc39a7ebbcda0638c`.
Previous latest release tag: v0.11 (`229f86c`). v0.10 established the desktop;
v0.11 added boot/greeter recovery, terminal selection, Bluetooth radio power and
startup refinements. Starting HEAD already contained native single-column
centering, overview cache, semantic Matugen mapping, runtime theme bundles,
Brave lifecycle-only opt-in refresh and pinned Spotify integration. These stable
subsystems were retained rather than rewritten.

The initial deployment manifest and active theme revision were recorded locally
before changes. The active wallpaper was the blue/violet `wallhaven-ogggkp.png` image, fill mode;
its content hash remained identical after installation and theme rollback.
The shipped fresh-install default remains separately configured in the repository. Browser was
already Brave, but directories/text used COSMIC and PDF/images used Brave. The
new explicit handlers are Nautilus/Papers/Loupe/GNOME Text Editor. Initial audit
artifacts contain private paths and are deliberately ignored, not published.

```sh

```

- Python suite: 103 tests, 102 passed, one opt-in Qt/Niri test skipped by default.
  That test was then run explicitly and passed (stream ordering, actions,
  disconnect/reconnect snapshots).
- Native Nothing backend: nine Rust tests passed, formatting and Clippy passed.
- Shell syntax/style, QML lint/format, Lua/Python parsing and native generated
  Niri/Hyprland validation passed.
- Isolated clean-HOME core/full dry-run tests write no user configuration/state.
- Existing-state fixtures cover unrelated MIME associations, shell/browser/Steam
  data preservation, managed-key conflicts, interrupted publication, original
  backup retention, core-to-personal role change and legacy MIME migration.
- Spotify fixtures cover known-pin upgrade, unknown source refusal, publication
  failure recovery, interrupted backup recovery and modified-binary refusal.

Hosted runs exposed missing Lua and an unintended Niri dependency in an isolated
Ubuntu ownership test. The workflow now installs Lua 5.4 for real rendering; that
fixture mocks only native `niri validate` and service side effects. Production
validation is unchanged and `scripts/check` validates real native Niri/Hyprland
on the reference Arch-family session. Hosted tests do not certify native parsing.

These fixture tests do not constitute a physical fresh-OS installation.

## Theme transaction and cost

A controlled orange source changed semantic accent to `#ffb596` while graphite
background/elevated stayed `#252429` / `#38363c`. Generated Niri, terminal,
notification, Brave, Spotify and cached overview outputs were inspected. Native
GTK accent changed through its supported enum and returned to blue on rollback.
The exact prior wallpaper revision/palette and image hash returned. No test
wallpaper remains active.

Latest measured cached apply: approximately 0.46s; unchanged apply: 0.09s total
CLI wall time. The no-op kept the current revision pointer. One swaybg remained,
zero resident Matugen processes. A short two-second running-session sample found
0% CPU for Quickshell, swaybg, wl-clip-persist and Mako; this is a sample, not a
promise of zero CPU under interaction. Niri was active with a game running, so
it is not an idle compositor benchmark. No latency/kernel tuning was added.

## Physical boundary and release decision

No OS was wiped, no fresh OS was installed, and lucky38 was not physically tested.
Main/LTS boot, graphics geometry, sound devices and first-login behavior on a new
machine retain the documented physical checklist. This warrants prerelease
installation-candidate status rather than calling installation fully certified.
Millennium/Material/Steam palette integration is explicitly excluded, not passed.
Account login remains the user's action. Full installation depends on the verified
ChatGPT package being available in configured signed repositories.

Private screenshots, raw process/session data and local audit logs remain ignored.
