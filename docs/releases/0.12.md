# Desktop Foundation v0.12

A Niri-first desktop with a clearer installation model, transactional
wallpaper-driven graphite theming and safer application defaults.

**Installation-candidate prerelease.** Automated and reference-session checks
pass; a physical fresh-OS install and second-machine acceptance remain pending.
This is a substantive upgrade from v0.10/v0.11, not a claim that those physical
installation paths have already been certified.

[View the real-session screenshot gallery](../screenshots/README.md).

## Installation and applications

Two entry points share one implementation:

- `./scripts/install-core`: the complete desktop, terminal, shell surfaces,
  wallpaper/theme engine and essential services.
- `./scripts/install-all` (or `./scripts/install`): core plus Brave Origin Nightly,
  pinned Spotify/Spicetify/Marketplace, verified ChatGPT desktop and stock Steam.

Both provide read-only `--dry-run` and `--check`. Existing managed paths are
checked before mutation. Original backups survive reruns; externally replaced
paths stop convergence. Unrelated packages are not removed, account data is not
imported, another login manager is not forcibly replaced, and the distro's
boot/initramfs stack is not converted.

Application roles now have one manifest. Core browser is Firefox; personal browser
is Brave Origin Nightly. Nautilus opens directories, Papers PDFs, Loupe PNG/JPEG,
and GNOME Text Editor plain text. MIME changes and restoration affect only owned
keys, preserving unrelated associations and later edits. Terminal/files/browser
shortcuts use these checked roles.

Brave prefers configured signed packages with reviewed AUR fallback. ChatGPT uses
the actual `chatgpt-desktop-bin` signed package available in the reference CachyOS
repositories; an unavailable source stops personal provisioning instead of adding
a foreign repository or substituting a different application. Steam requires a
configured native package source/multilib.

**Millennium, Material and Steam wallpaper-color integration are excluded.**
Loader activation and native theme selection have not passed live acceptance.
Stock Steam provisioning does not alter userdata, game libraries or client branch.

Spotify's one-time login and normal quit/reopen complete first-run patching.
Known owned Spicetify 2.45.1 can upgrade to 2.45.3 with an original-tool backup;
unknown binaries refuse replacement. The read-only check verifies paths, tools
and managed colors without parsing account preferences.

## Niri and terminal

Native `always-center-single-column` centers a solitary tiled column while
`center-focused-column "never"` retains normal multi-column scrolling. Manual
Super+C remains. Finnish input, existing bindings, 14px window treatment,
96% ordinary opacity and Kitty's native 90% background/opaque glyphs are preserved.
The existing full-scrollback Kitty selection and 10,000-line limit remain.

Niri screenshots copy to clipboard. The region selector completes on release;
Print captures the output. Hyprland's separately documented screenshot storage
policy remains different.

## Wallpaper and graphite themes

`./scripts/wallpaper-set /path/to/image` performs a one-shot Matugen generation,
restrained semantic graphite mapping, adapter rendering/validation and atomic
runtime-revision publication. Wallpaper, palette, cached blurred overview and
outputs roll back together. Cached unchanged applies do not publish a revision.
Normal wallpaper changes do not dirty the repository. No theme daemon is added.

Adapters cover Quickshell surfaces/volume readout, Niri, Kitty/Fish/Fastfetch,
notifications, Brave generated theme and Spotify colors. Supported GTK native
accent enums follow the palette without CSS overrides. Sharp desktop wallpaper
and prepared blurred overview remain separate.

Repeated wallpaper transactions now explicitly reset only the wallpaper unit's
start-limit counter before restart. Automatic crash protection remains enabled;
rapid apply/rollback no longer leaves the wallpaper stopped.

Brave keeps one stable unpacked-theme directory and identity. Native import/reload
is the default; lifecycle-only approved DevTools refresh remains explicit opt-in
and OFF. Normal installation never edits browser profiles. Spotify updates assets
without restarting; a running client needs native Reload or next launch.

## Upgrade and recovery

Keep the deployed checkout in its permanent location, update it to this tag and
inspect `./scripts/install-all --dry-run` before convergence. Use `--no-greeter`
when retaining another display manager. The installer migrates legacy owned MIME
metadata without discarding unrelated defaults. Existing runtime wallpaper is
retained when deployment refreshes templates.

`theme-rollback` restores the prior runtime theme. `scripts/uninstall` restores
journaled user configuration/native settings; packages and account data remain.
Privileged boot/AppArmor/greetd changes have separate restore commands and retain
service enablement. Backups and ownership manifests must remain available.
