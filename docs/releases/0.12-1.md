# Desktop Foundation v0.12-1

**Prerelease — maintenance, reliability and Rust backend improvements after v0.12.**

This source candidate has passed the complete available local static and isolated
integration checks. It has **not replaced the live lucky38 desktop**. Live
candidate deployment, visual acceptance, resident RAM comparison, real idle CPU
comparison, Nothing/CMF physical hardware acceptance, volume/audio physical
acceptance and complete live session acceptance remain pending. It is not
live-certified.

## Rust backend

A reusable `desktop-foundationctl` now supplies Rust clipboard storage/actions,
application-role launching, an action registry, volume handling, power/session
actions, package-information caching, shell IPC readiness and guarded cache
maintenance. Shared typed code provides locks, atomic state publication and
bounded subprocess execution. Existing formats and native handoffs are preserved.
No new resident daemon, persistent backend/service or network listener is added.
Nothing/CMF remains a separate on-demand Rust device backend.

## Performance

Paired clipboard measurements alternate old/new order after two warmups, use fresh
private databases on the same filesystem and synthetic payloads, and include
process startup and filesystem publication. These specific helper benchmarks are
not evidence that the entire live desktop uses less resident RAM or CPU. Power
and frequency state were not recorded; foreground activity was not controlled.

| Helper benchmark | Median before → after | Peak helper RSS before → after |
|---|---:|---:|
| Text storage, 9,728 bytes; 24 samples each | 52.279 ms → 9.850 ms | 22,910 KiB → 4,796 KiB |
| Image storage, 1 MiB; 10 samples each | 74.531 ms → 17.025 ms | 30,524 KiB → 8,866 KiB |
| Nothing parser corruption recovery; 36 samples each | 22.922 ms → 0.0326 ms | Not measured |

Clipboard projections match across implementations. The image fixture measures
storage/signature behavior, not image decoding. The parser stress case contains
65,536 garbage bytes followed by an exact valid packet; it measures corruption
resynchronization, not ordinary hardware latency or idle CPU.

Hot caller paths avoid redundant wrapper/interpreter starts. Required native
commands remain where replacing them would duplicate working upstream services.
Hashing streams data instead of allocating a complete file solely for hashing.

## Reliability

- Stalled Niri requests recover through bounded deadlines and reconnect/resnapshot
  behavior. Actions with unknown outcomes are never replayed.
- Subprocess time and captured output are bounded. Nonblocking pipe handling
  prevents detached pipe holders from extending deadlines; successful clipboard
  ownership handoffs survive.
- Clipboard/cache publication is atomic, with interrupted clipboard publication
  recovery and useful errors instead of silently resetting a database.
- Preference restoration resumes after partial or interrupted writes and preserves
  externally changed settings.
- Screenshot errors are distinguished from cancellation; negative geometry and
  invalid output are checked without imposing a timeout on user region selection.
- Deployment checks both required release binaries before changing configuration.
- Doctor preserves native diagnostics and recognizes genuine empty shell results.
- Nothing input/protocol handling rejects malformed and oversized commands, avoids
  quadratic packet resynchronization and removes malformed-gesture panic paths.
- Theme/cache retention is bounded and respects ownership and rollback pointers.
- Copied theme bundle helpers use their owning checkout and revision configuration.

## Storage and runtime

Retention protects current/previous theme revisions while bounding recognized
owned revisions to six, palette caches to 32 and overview PNGs to 16. Active
references, originals, journals, foreign state and symlinks are protected. Cleanup
runs after deliberate successful publication, not through a resident polling loop.

Generated development incremental-cache cleanup reclaimed approximately **241 MiB**
in the isolated quality checkout; original build artifacts and live caches were
not cleaned. Combined runtime Rust executables grow by about **0.74 MiB**:

- `desktop-foundationctl`: **1,140,888 bytes** in the recorded quality-pass build.
- `foundation-nothing`: **4,287,744 bytes**, down from 4,655,416 bytes.

Release builds are repeated before publication; toolchain/build differences can
change exact executable sizes. The development measurement binary is not deployed.
Nothing's lockfile shrinks from 85 to 79 entries; the shared backend uses system
SQLite and does not add a GUI or async runtime.

## Preserved desktop design

QML rendering remains QML. Shell visual definitions are unchanged: layout,
spacing, fonts, blur, opacity, animations and accent/graphite/glass design are
preserved. Existing Niri event-driven behavior and native Quickshell data providers
remain. No new steady-state polling daemon exists. Pixel-comparison tests preserve
blur output; source preservation does not replace pending live visual acceptance.

## Validation

The completed quality pass recorded **138 Python/integration tests** and **36 Rust
tests**, passing locally. Final publication validation repeats the complete suite,
including both isolated Qt fixtures, and records any changed counts before tagging.

Release gates include Cargo formatting, warnings-denied Clippy, Rust tests, both
release builds, `scripts/check`, `scripts/test`, shell checks, QML lint/format,
Lua/Python syntax, Fish syntax and native Niri validation for default, Tops,
lucky38 and missing-profile fallback. QML lint has existing installed-metadata
warnings; it is not warning-free. Hosted portable checks do not certify live UI,
physical graphics, audio/Bluetooth or login/boot behavior.

Git history retains the logical quality commits and the public main CI/portable
test fixes. No existing v0.12 history or tag is rewritten. Publication performs no
live deployment, desktop reinstall, install-all, cleanup/migration replay or
login-manager change.
